# Projected registered-condition development protocol

**Fixed:** 24 October 2026 UTC, after pilot-size results and before this conditional audit. This is an exploratory development test, not independent Adult confirmation or cross-condition generalization.

Use the six fixed projected cells (Chow-Liu age/K5 and mixed-GMM label-skew/K10, seeds101/202/303), size and fixed constrained weights. Train each conditional student **only from a 30,000-row released-model teacher draw**, no real held-out row. For each of the four starter registered conditions in `btp.evaluation.CONDITIONS`, fit a Chow-Liu feature-only estimator to teacher rows satisfying that condition, using declared public numeric bounds/categories and the public education-code projection. Student generation requests 2,000 rows and filters violations; direct teacher rejection uses an independent 30,000-row model draw, with the same number of accepted evaluation rows as the student (up to 2,000). Save the fitted student, teacher acceptance/route cost, raw student violation, accepted row count and both synthetic query answers.

The server supports a condition only if the teacher pool contains at least 300 matching rows and at least 1% mass; otherwise it abstains without a fitted student or fabricated successful row. The privileged evaluator records alpha-standardized real development-assessment condition mass/count and within-condition feature-query error where real support exists. Use the version-2 feature workload with income queries removed; record all component query answers and max/mean error. A student is preferable to direct rejection only if it lowers within-condition error without material condition violation or excessive filtering cost. This per-registered-condition estimator cannot answer an arbitrary unseen condition; any cross-condition generalization claim remains untested. Keep official Adult test and seeds404/505 locked, the shared lease and one-thread resource reserve, and all failures.
