# Frozen order of twelve research work packages

The driver runs real computations for each numbered stage. A green smoke marker means software executes, not that the scientific work package is complete. The EC2 agent must complete the broader grids and audit the stated limits. Do not reorder or merge the numbers.

## Frozen decision and publication gates

Default CLI runs use a second development holdout, formed by a full-record-hash split of the initial validation pool, as the assessment reference. They never score official-test rows. Official test is gated behind `--official-test --selection-file`; the frozen file declares `method` and `test_used_for_selection: false`. Inspect the `reference_role` in every configuration before describing any `exp*_test.csv` table. During development, repeat conditional/predictive/resource analyses for each viable candidate family, rather than assuming the best unconditional-fidelity method is the best overall. Extend the starter's selected-method analysis loop accordingly within the budget.

Choose the final method on development validation cases, then freeze it before confirmatory evaluation. After all twelve packages, write a paper only around what actually survives the evidence and novelty audit. A collection of twelve completed scripts by itself is not a novel method or proof. A valid final result may be that size weighting is preferable, particular calibration helps only biased local models, or some conditional requests need abstention.
